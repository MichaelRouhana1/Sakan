# OSM streets and neighbourhoods (offline tooling)

Not a runtime service. Produces a reviewable seed and `REVIEW.md`; nothing is imported until the review is approved.

```
python -m venv .venv && .venv\Scripts\pip install -r requirements.txt

node export-anchors.mjs          # read-only DB export: ranking anchors + current catalog -> out/
.venv\Scripts\python osm_extract.py   # Geofabrik lebanon-latest.osm.pbf (md5 verified) -> out/raw.pkl
.venv\Scripts\python osm_build.py     # area-map.json polygons, clip, merge per name per area -> out/candidates.json
node osm_review.mjs              # dedupe with the real normalize v2 in a rolled-back txn -> streets.seed.json + REVIEW.md
node check-normalize.mjs         # golden vectors for normalize v2 against Postgres
node export-map-data.mjs         # seed + polygons -> artifacts/osm-streets/maps for the Leaflet spot-check page
```

`decisions.json` is the approved list (hoods, alias additions, dropped streets, extra aliases). Edit it, rerun `osm_build.py` and `osm_review.mjs`, then `npm run db:search:osm-apply` from `backend/`.
Arabic-only streets get `street:<area-slug>-osm-<way id>` ids (hyphenated so the id stays inside the shared `[a-z0-9-]` id pattern); their English label is the Arabic name.

- `area-map.json` is hand-maintained: curated area -> OSM polygon, or a derived circle where OSM has none.
- `normalize_v2.sql` is generated by `gen_normalize_sql.py` and is the single source for the immutable `search_normalize` (migration 0044, after review). `st` is not a generic word.
- Scope: every named street inside a mapped polygon. Anchor density only ranks.
- Radius is per parent area: 400 m Beirut, 800 m Matn and towns.
- Data © OpenStreetMap contributors, ODbL.
